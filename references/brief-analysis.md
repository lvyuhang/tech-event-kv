# 需求分析（第 1 步，必须先做完）

拿到 brief 之后，**不要立刻想概念**。先把这场活动是什么、给谁办、为什么办、在哪里用弄清楚。过去几次失败（风格错配、"连接"没画出来、配色不明快）都可以追溯到这一步只是在"抄字段"，没有理解需求。

产出写进项目 `concept.md` 的第一节「需求分析」，**交给用户确认后**才进入调研和概念。

---

## 一、九个问题

每个问题都要有结论；不知道的写进"待确认问题"，不要自己编。

### 1. 活动性质：这是什么类型的活动？
- 拆开活动名里的每个成分。例如"成立仪式**暨**校园宣讲会"是两件事：成立仪式（有启动感，可能有揭牌、合影）+ 宣讲会（面向学生拉新、科普）。
- 判断**类型**（见 `genres.md`）：运营招募 / 校园、开发者大会 / 技术峰会、品牌发布、黑客松 / 社区。类型决定了视觉惯例和评审标准。
- 一句话写出**活动目的**：KV 要让看到的人做什么？（来现场、报名、加入、记住品牌……）

### 2. 主办方是谁，关系是什么？
- 每个主办 / 协办 / 技术方：它是做什么的、在这次活动里扮演什么角色、品牌调性如何、有没有 VI 规范、有没有 IP 形象或吉祥物。
- **主次关系**：谁是主角？logo 怎么排序？画面应该更像谁？
- 用搜索确认事实（产品是什么、开源在哪里、学校的历史和特色），**不要凭印象**。查不到的写进待确认。

### 3. 受众是谁，他们知道什么？
- 年龄、身份、专业、对主题的熟悉程度（例如：大多数学生没听过"算子"）。
- 他们在哪里看到 KV（朋友圈、公众号、教学楼海报、现场大屏）、看多久、被什么吸引。
- 结论：画面要用**受众的语言**说话——专业术语要不要出现？出现时靠什么让外行也觉得有意思？

### 4. 关键词拆解
把 brief 和文案里的关键词逐个拆开，写出每个词的**含义 / 情绪 / 可视化的东西**：

| 关键词 | 含义 | 情绪 | 可以画什么 |
|---|---|---|---|
| 成立 | 第一届、起点 | 期待、仪式感 | 启动、点亮、剪彩、第一块积木 |
| …… | | | |

然后归纳出**核心情绪**（一个词）和**必须被看出来的信息**（2–3 条）。

### 5. 风格要求翻译
用户写的形容词要翻译成**可执行、可检查**的视觉参数，并给出参照：

| 用户原话 | 翻译成视觉参数 | 反面（不能做成这样） |
|---|---|---|
| 年轻化、校园感 | 互联网校招 / 社团招新的视觉语言：3D 潮玩物件、贴纸、角色或手 | 舞台发布会、商务蓝 |
| 轻松活泼 | 明亮、饱和、多元素、动感（倾斜、运动模糊、漂浮） | 安静、克制、留白大于 60% |
| 明快有活力 | 高明度底色（白 / 浅蓝 / 浅紫）+ 2–3 个饱和点缀色 | 深色底、暮光、雾、低饱和 |
| …… | | |

**翻译不出来、或者有两种理解时，问用户**，并附参考图让用户选。

### 6. 必须出现的元素 / 必须表达的关系
- brief 里点名的元素逐条列出（校园、代码、算子、AI 计算、科技感……），标注主次。
- brief 里要求表达的**关系**（如"社区与高校开发者之间的连接"）单独列出：关系必须在画面里**被看见**，通常需要两个主体 + 一个动作（握手、击掌、传递、并肩）。

### 7. 使用场景与延展
- 每个使用场景的观看条件：现场大屏（远看、可能被舞台遮挡、可能作为合影背景）、线上（缩略图、公众号头图裁切）、印刷物料。
- 需要延展哪些物料？延展需要哪些**可拆分的元素**（单独的 IP、物件、图形）？

### 8. 文案与层级
- 标题多长？怎么断行？哪部分最大？
- slogan 是在讲什么？画面能不能直接把 slogan 画出来？
- 用户指定的层级（"突出活动名称和 slogan，时间地点辅助"）原样写进验收清单。

### 9. 约束与风险
- 品牌规范（logo 安全区、标准色、字体）、多方审核、校名 / 校徽使用规范、字体授权、未确认信息（场地、日期）。

## 二、验收清单（从上面九条生成）

把需求转成**能逐条打勾**的清单，写进 concept.md。第 7 步自检时**先过这张清单**，任何一条不满足，不管审美分多高都不能交付。

```
□ 一眼能看出是面向高校学生的开发者活动
□ 风格：年轻、校园、轻松活泼（对照 genres.md 该类型的惯例）
□ 配色：明快有活力，不是深蓝科技风
□ 元素：校园 □  代码 □  算子 □  AI 计算 □  适度科技感 □
□ 关系：社区 ↔ 高校开发者的"连接"在画面里被看见
□ 层级：活动名称 + slogan 最突出，时间地点为辅
□ 文案逐字正确
□ 16:9，现场大屏远看可读
```

## 三、待确认问题

分析完列出需要用户回答的问题，**一次性问完**。常见的：
- 主次关系和 logo 顺序；各方 logo 文件与 VI
- 有没有现成的 IP 形象 / 吉祥物可以用
- 参考图：用户心目中"对"的样子（至少 3 张），尤其是调研里看不到图的时候
- 未确定的信息（场地、日期）
- 是否有特殊用途（签到墙、合影背景板）

用户没有回应时，按最合理的理解继续，并在交付里标明假设。
