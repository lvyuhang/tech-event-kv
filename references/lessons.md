# 经验库：踩过的坑

每条按"症状 → 原因 → 修正 → 规则落在哪"记录。执行 skill 时，第 7 步自检要逐条对照；遇到新问题，按同样格式追加到末尾。

来源标注：`[评审]` 来自用户 / 设计师评审，`[自检]` 来自执行者自己发现。

---

### L01 隐喻直白 [评审]
- **症状**：AI 大会 → 神经网络；云 → 云朵。
- **原因**：从关键词直接找图标，跳过了"主张"。
- **修正**：先写主张，再走字面层 → 感受层 → 世界层，用造境手法发散。
- **规则**：concept.md 第 1–4 步；直白度 L0/L1 直接淘汰。

### L02 主体像贴纸 [评审]
- **症状**：一个物体放在渐变背景上，两者没有物理关系。
- **原因**：提示词是"物体说明书"，先写主体后写背景。
- **修正**：提示词先写世界，再写主体，必须有"互动"段（光溢出、倒影、接触、纵深）。
- **规则**：prompt-recipes.md 7 段结构；integration.md 七种融合手法与禁用短语。

### L03 排版初级、默认字体 [评审]
- **症状**：系统默认字体，标题 / 副标 / 日期从上往下堆。
- **原因**：没有字体选择环节，也没有排版系统。
- **修正**：字体配方 + 排版系统；渲染时检测字体是否加载。
- **规则**：typography.md；render.py 的 ⚠ 字体警告必须处理。

### L04 没用上活动名 [自检]
- **症状**：做了"光标灯塔"，活动叫"星河"却完全没用上。
- **原因**：发散时只围绕主题，没看活动名本身。
- **修正**：先问活动名、品牌名里有没有现成的画面。
- **规则**：concept.md 第 0 步。

### L05 巨字挡住叙事焦点 [自检]
- **症状**：GALAXY 巨字盖住了"光河与银河相接"的位置。
- **原因**：巨字按中间带居中，没有考虑画面焦点。
- **修正**：`mark_baseline` 让巨字立在地平线上；或换位置。
- **规则**：typography.md `bleed`；qa-checklist 常见问题表。

### L06 取色只取到一个色相 [自检]
- **症状**：主图有暖金和冷青，文字只拿到暖金，"从个体到整体"的冷暖叙事断了。
- **原因**：大面积背景淹没了主体颜色；第二色相阈值太高。
- **修正**：只统计鲜艳像素的色相直方图；阈值降到 2%。
- **规则**：render.py `palette_from_image`。

### L07 执行老气 [评审]
- **症状**：创意认可，但画面像 2015 年的星空壁纸：紫金配色、金色散景、渐变巨字。
- **原因**：生图 / 写实的默认审美落在老气一侧；没有"时代感"检查项。
- **修正**：对照老气信号表；换成生成式 / 图形化语言；配色收到"近黑 + 冷白 + 1 个强调色"。
- **规则**：contemporary.md 第一节；评分第 8 项。

### L08 大字撑不住细节 [评审]
- **症状**：占画面 40% 的字只是一块渐变，大屏上显得简陋。
- **原因**：巨字没有内部细节、没有穿插。
- **修正**：纹理填充（如代码纹理）、主体从字前穿过、或精确的周边系统。
- **规则**：contemporary.md 第三节；`lockup` 的 `mark_fill: texture`。

### L09 识别度低 [评审]
- **症状**：遮住文字，画面换给任何技术活动都成立。
- **原因**：没有可拥有的视觉装置。
- **修正**：用活动名的字 / 专属的形 / 专属的材质语言做装置，贯穿所有尺寸。
- **规则**：contemporary.md 第二节；第 3 步每个方向要写明装置。

### L10 图形和文字被裁切 [评审]
- **症状**：巨字笔画上下端被切平；画面边缘的字符被切一半；流的尾巴出画。
- **原因**：`background-clip: text` 只在行框内绘制、行高 < 1；生成图层没检查边界；用裁切代替单独生成。
- **修正**：填充字加绘制内边距；生成时只保留完整在画面内的元素；每个尺寸单独生成。
- **规则**：contemporary.md "要么完整，要么大胆出血"；qa-checklist 硬性检查。

### L11 透镜放在空白处 [自检]
- **症状**：玻璃透镜像一颗白球。
- **原因**：透镜下方只有空白纸面，放大的是空白。
- **修正**：透镜放在内容密集的区域，让边缘弯折的内容可见。
- **规则**：contemporary.md 第四节。

### L12 高端品牌做成了"落地页" [评审]
- **症状**：给 Apple 做的稿有顶栏、标签网格、代码注释，像开发者工具的网页。
- **原因**：把"排版系统"当成品质；没有按品牌调性做减法。
- **修正**：一张图 + 一行字（`invite`）；主体必须高精度。
- **规则**：contemporary.md 第五节；typography.md `invite`。

### L13 自评虚高 [评审]
- **症状**：给替身图打了 35 分，用户评价"明显达不到 Apple 的品质"。
- **原因**：单独看自己的图打分；替身图的渲染质量被算进了成品分。
- **修正**：和天花板作品并排打分；替身图的冲击、融合最高 3 分；高端品牌以其往届物料为基准。
- **规则**：qa-checklist "评分校准"。

### L14 让模型画准确的文字 / 代码 [自检]
- **症状**：透过玻璃看到的代码必须准确，模型画不出来。
- **原因**：把"内容"和"光影"都交给了模型。
- **修正**：模型只出光影（透明物体放在空白纸面上），内容由排版生成后合成、折射。
- **规则**：SKILL.md 第 4 步路线 D；`scripts/compose_photo.py`。

### L16 扁平 / 插画类方向不必等生图模型 [自检]
- **症状**：把所有方向都当成"要生图模型才能出成品"，结果只能交替身图。
- **原因**：没区分写实类和图形类方向。
- **修正**：年轻、校园、扁平图形类方向（跑道、地图、贴纸、票据）直接用 SVG / HTML 画成品，精度足够。
- **规则**：SKILL.md 第 4 步路线 F；示例 `examples/tju-cann/`。

### L17 贴纸 / 标签挡住关键内容 [自检]
- **症状**：起点贴纸被日期小票盖住；贴纸又挡住了第 1 道代码的开头。
- **原因**：装饰元素随手摆放，没检查层级和遮挡。
- **修正**：先定信息元素的位置，再放装饰；装饰只能压在纹理上，不能压在要读的内容上。
- **规则**：qa-checklist 可读性检查。

### L18 被实现手段限制了视觉 [评审]
- **症状**：为了"可编辑"交了 SVG 扁平插画，完成度不够；用户说不需要 HTML，在意叙事和视觉完成度。
- **原因**：把输出格式当成了目标，选了最容易做的手段。
- **修正**：交付位图；同一个概念升级为有纵深、光影、景深的场景（路线 G），再用扁平贴纸做年轻感的拼贴。
- **规则**：SKILL.md 硬规则 0；路线 G；`scripts/photo_post.py`。

### L19 需求分析基本没有 [评审]
- **症状**：天大 CANN 校园宣讲会：风格要求、活动关键词、主办方背景、受众都没深入分析，直接从 brief 跳到概念。
- **原因**：第 1 步只是收集字段，没有理解需求。
- **修正**：九个问题的需求分析 + 验收清单 + 待确认问题，作为关卡交用户确认。
- **规则**：SKILL.md 第 1 步；`brief-analysis.md`。

### L20 用错了类型的审美标准 [评审]
- **症状**：用「克制、独特、高级」的标准做校园活动，把吉祥物、多元素当成扣分项；结果不年轻、不活泼。
- **原因**：skill 的审美体系来自品牌发布和开发者大会，默认套用到所有活动。
- **修正**：先判断活动类型，按类型的惯例和评分权重。校园 / 运营类用 3D 潮玩、手、贴纸、高明度配色、定制标题字。
- **规则**：`genres.md`；qa-checklist 类型权重。

### L21 跳过风格确认、没要参考图 [评审]
- **症状**：调研看不到图时没有向用户要参考；用户说「你来定」就直接做到底，三轮都偏了。
- **原因**：把「你来定义」理解为「不用确认」。
- **修正**：两道关卡必须停；「你来定」时给出推荐项，但仍要用户选。调研无图时必须要参考。
- **规则**：SKILL.md 硬规则 1、第 1.5 步、第 3 步。

### L22 「连接」没有被画出来 [评审]
- **症状**：brief 要求体现「社区与高校开发者之间的连接」，画面是一条没有人的跑道。
- **原因**：需求里的「关系」没有单列成验收项。
- **修正**：关系需要两个主体 + 一个动作（击掌、握手、传递、并肩）；写进验收清单。
- **规则**：`brief-analysis.md` 第 6 条。

### L23 技术元素要长在物件上 [评审]
- **症状**：用户提醒"要有技术元素融入"。校园潮玩风格容易只剩可爱物件，技术感变成背景上的电路纹。
- **修正**：技术元素做成物件上具体可读的内容：算子名键帽、真实代码片段、Merged 徽章、芯片里的光。
- **规则**：`genres.md` A 的硬要求；`prompt-recipes.md` 的 tech_details 段。

### L24 没有生图模型时，潮玩物件用 three.js 搭 [自检]
- **症状**：用户要求"你来试试生成"，环境里没有生图模型，npm 也不可用。
- **修正**：用 git 稀疏克隆 three.js（GitHub 可达），本地 http 服务 + SwiftShader 渲染；物件全由圆角几何体拼成，文字用 canvas 贴图写在物件表面；前景一层单独渲染后虚化；标题在 HTML 里做黑字 + 白描边 + 北洋蓝挤出 + 速度线。
- **注意**：袖子上的徽章要贴在朝向镜头的那一面，镜像的手要把贴图再镜像回来；文字贴片宽度要小于圆柱可见宽度，否则会被裁掉。
- **规则**：`genres.md` A 的主图路线。

### L25 元素乱、字效老气 [评审]
- **症状**：天大 KV 第一版，用户评价"元素有点乱，文字效果不够精致，阴影看起来老气"。画面有 13 个物件、9 颗闪光；标题用了白描边 + 北洋蓝实色挤出 + 速度线 + 假斜体，slogan 气泡带偏移实色阴影。
- **原因**：把"热闹"理解成"多"；把参考图的手绘标题字理解成"加描边加投影"。
- **修正**：物件减到主角 + 左右各 2 个，左右成对、角度收敛；标题改为干净超粗黑体 + CANN 渐变 + 柔投影，slogan 用磨砂胶囊。
- **规则**：`genres.md` A 的"宁少勿乱""标题字要精致"。

### L26 道具和漂浮元素没有创意 [评审]
- **症状**：用户用 image-2 出的图质感很好，但评价"问题在创意层面：手里拿的东西是什么、上面展示什么信息、漂浮元素应该是什么"。手里是"z = x + y"的窗口 + add 键帽，周围是复古电脑、PR 气泡、光标、`</>` 键帽——全是类型通用道具，换任何编程活动都成立。
- **原因**：概念停在"两只手交接"这个动作，没有设计被交接的东西；漂浮物件按"校招潮玩清单"挑，没有组织逻辑。
- **修正**：主道具做成"第一个算子"的实体（张量进、张量出的玻璃积木），由学生交给社区；漂浮元素组成"两个世界 + 同一家族"：左边天大（海棠、北洋 1895），右边社区（其他算子积木搭成的、立在芯片上的模型，留着一个空位）。
- **规则**：`concept.md` 第 5.5 步。

### L27 机制主体做成了纯技术、没有焦点 [评审]
- **症状**：用户评价"看起来非常纯技术，且画面构成混乱"。缎带上依次是终端、代码卡、张量方块、NPU 芯片框、PR 卡、Merged、头像流，共 7 处文字标签；缎带拐成 S 形，物件大小相近。
- **原因**：把 slogan 翻译成开发者的工作流，每一站都用了术语；照搬参考的"站点"结构，却没照搬它"一个焦点 + 一道弧 + 通用图标"的构成；去掉了人。
- **修正**：只保留一个焦点（Q 版学生举着发光的"第一个算子"积木），缎带改成一道弧，社区用伸手接应的伙伴表现，画面里只留一个词。
- **规则**：`concept.md` 机制主体的三个陷阱、第 5.5 步自检的外行 / 焦点 / 字数测试。

### L28 大学生画成了小孩 [评审]
- **症状**：提示词写"Q 版学生、背着书包"，用户提醒"这里的学生是大学生"。
- **修正**：人物用年轻成人比例和大学生的穿搭；提示词的 avoid 段写明不要 Q 版大头、儿童、书包、校服。
- **规则**：`genres.md` A "人物年龄要对上受众"。

### L29 AI 感很强、不好看 [评审]
- **症状**：image-2 出的"大学生举着积木走上坡"，用户评价"AI 感很强，并不好看"。
- **原因**：到处发光、没有暗部；全身皮克斯式人物，表情和姿态是模板；人物仰拍、校园俯拍，视角混杂；材质都是糖果玻璃；云上漂浮的校园；画面全部来自模型，设计层只有旁边的文字；故事演得太字面。
- **修正**：只用手或局部；分别生成单个素材，在排版里统一视角、光和调色；加上锐利的设计层（网格、贴纸、标签、标题和物件穿插）；后期压掉泛光、拉回暗部。
- **规则**：`contemporary.md` 第六节。

### L30 人物状态与场景 [评审]
- **症状**：用户给出快手"票选有礼"的潮玩人物，说明"人物应该是这种状态，不能出现写实场景"。
- **修正**：人物改为潮玩手办风（成人潮流穿搭 + 简化五官 + 软胶材质），在做和活动相关的事；背景只用纯色 + 地面 + 道具布景。L28 的"6–7 头身"规则被这条取代。
- **规则**：`genres.md` A 的人物与场景规则。

### L31 太执着于画面叙事 [评审]
- **症状**：用户问"我们是不是太执着于画面叙事了？"。天大项目连续几轮在改"手里拿什么、谁给谁、每个物件代表什么、slogan 的路径"，画面越来越字面、越来越乱，AI 感越来越强，而用户给的参考没有一张是靠剧情好看的。
- **原因**：把开发者大会 / 品牌类的"概念驱动"方法套到运营类；每次评审只加叙事规则，没有回到"好不好看"。
- **修正**：运营类的优先级是调性与好看 → 标题字 → 一个主符号 / 动作 → 物件氛围；叙事只要一个动作满足"连接"，其余交给文案。
- **规则**：`genres.md` A 开头；`concept.md` 第 5.5 步的轻量版说明。

### L32 迁移后骨架的识别特征丢了 [评审]
- **症状**：抖音"心动街区"迁移到天大 CANN 后，用户评价"路杆的特征不明显，中间的元素偏复杂"。杆子上挂的是成员卡、金属设备、角色立牌、玻璃 UI 卡，挤在一起挡住了杆子，杆顶的 CANN 立体字又太大。
- **原因**：填槽时把"牌子"整个换成了别的物件，只保留了内容，丢了形状；每个槽位塞的东西比参考复杂。
- **修正**：杆子完整可见；路名牌 "CANN Rd." + 两块方向相反的箭头牌（"从第一个算子" ← → "到第一份贡献"），slogan 由路牌本身讲完；角色坐在牌子上，设备缩小成挂件。
- **规则**：`reference-transfer.md` 的"形式保持"和"识别特征"。

### L33 创意没考虑主物料是线下印刷板 [评审]
- **症状**：推荐了登机牌、贴纸笔记本、招新摊位，用户指出"这是要线下打印出来的 KV 主视觉板子，有些创意不合适"。
- **原因**：提方向时只想创意，没回到使用场景；需求分析写了"大屏兼合影背景"，但没把它变成对创意的筛选条件。
- **修正**：按印刷板子的约束逐个筛方向：信息字段多的载体（登机牌）改做手持物料；主体在画面中下部的场景微缩（摊位）会被人挡住；贴纸笔记本元素小而碎，适合周边。
- **规则**：`sizes.md` 末节"线下印刷主视觉板"；`brief-analysis.md` 第 7 条。

### L34 主 KV 太碎、不大气 [评审]
- **症状**：用户评价模块拼贴"太碎了，主 KV 还是得大气一点，一眼有技术氛围、年轻氛围"。
- **原因**：把"热闹"做成了很多小块；印刷板远看时小块变成噪点。
- **修正**：活动名做主体：3D 立体字 "> CANN_"（提示符 + 光标 = 一眼技术；糖果感材质 + 明快配色 + 少量软胶星星和键帽 = 年轻），下面一行超大"开发者俱乐部"和 slogan 胶囊。
- **规则**：`sizes.md` 印刷板一节"主 KV 要大气"。

### L15 看不到搜索到的参考图 [自检]
- **症状**：图片搜索结果只展示给用户，执行者看不到图，拆解只能靠猜。
- **原因**：工具限制。
- **修正**：优先找设计方的项目说明页；没看过原图的条目标"（据说明）"；请用户补图。
- **规则**：research.md 第四节。
