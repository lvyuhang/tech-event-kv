# 参考迁移：给一张视觉参考，套到本活动上

用户只给一张参考、说"做成这样"时，**不是照着画，也不是只学个风格**。参考里有三层东西，处理方式不同：

| 层 | 是什么 | 怎么处理 |
|---|---|---|
| **骨架** | 构图结构、视觉重心、标题和主体的关系、信息区的位置 | **照搬** |
| **语言** | 材质、配色、光、标题字的气质、装饰手法 | **照搬**，配色可以换成本活动的主色 |
| **语义** | 每个元素在参考里扮演的角色和它的具体内容 | **全部替换**成本活动的内容 |

参考的品牌资产（logo、IP、吉祥物、品牌色组合、专属图形）一律不复制。

---

## 五步

### 1. 拆骨架
- 构图类型：主轴式 / 环绕式 / 左文右图 / 网格拼贴 / 中心物件……
- 视觉重心在哪、多大
- 标题怎么放：被主体劈开、压在主体上、坐在色块里、环绕主体……
- 信息区：底部色带、胶囊、搜索框……
- 画一张**骨架线框**：只有色块和标注，没有具体内容

### 2. 拆语言
- 材质（逐部位）、配色（取色值）、光、标题字（粗细、圆角、倾斜、描边、颜色）、装饰（贴纸、星星、棋盘格……）
- 写成可以直接放进提示词的风格段

### 3. 拆语义槽位
把参考里每个元素写成"**槽位**：它在画面里的角色"，不写它具体是什么。常见槽位：

| 槽位 | 角色 |
|---|---|
| 品牌符号 | 画面最高处或最中心的品牌标识 |
| 主轴 / 主体 | 承载其他元素的骨架（路牌杆、手、设备、缎带） |
| 内容卡片 | 挂在主体上的信息单元，每张一个关键词 |
| 身份符号 | 说明"这是哪里 / 谁办的"（城市地标、校园建筑） |
| 吉祥物 / 角色 | 情绪和亲和力 |
| 行动入口（CTA） | 告诉人下一步做什么（搜索框、按钮、二维码位） |
| 氛围点缀 | 星星、云、光、小物件 |

### 4. 填槽
用**第 1 步需求分析**里的内容填每个槽位：
- 品牌符号 → 主办方 logo 或活动的核心名词
- 内容卡片 → 活动关键词、必须出现的元素（每张卡一个，3–5 张）
- 身份符号 → 主办方的特征（学校、城市、产品）
- 吉祥物 → 有 IP 用 IP；没有就用本活动的一个可爱化物件（不要硬造新 IP）
- CTA → 时间地点、报名方式
- 每个填进去的东西都过一遍**双重相关**：和主题有关，也和受众有关（genres.md A）

**形式保持**：填槽时换的是**内容**，不是**形状**。参考里是路牌，迁移后还得是路牌形状（路名牌、箭头牌），内容写在牌子上；不能把牌子换成成员卡、设备、角色立牌——那样骨架的识别特征就丢了。同时保持参考的**元素数量和留白**：参考挂 4 块牌、彼此有空隙、杆子露出来，迁移后也一样，不要往槽位里塞更复杂的物件。
先找出参考的**识别特征**（这张图一眼认得出是什么，靠的是哪几个形状），迁移后逐条检查它们还在不在。

### 5. 过约束
逐条对照**用户已确认的约束**和需求分析的验收清单。冲突时按约束改槽位内容，在迁移表里写明怎么改的。例如"不能出现写实场景"→ 参考里的写实地标改成潮玩模型。

---

## 产出

1. **迁移表**：槽位 | 参考里是什么 | 本活动换成什么 | 为什么（和主题、受众的关系）
2. **骨架线框**（可选）
3. **提示词**：骨架段 + 语言段 + 逐槽位的内容段 + 文字段 + 约束（avoid）

示例：`examples/tju-cann/transfer-douyin-street/`。
